# Do's, Don'ts & Best Practices

## DO
- Keep the first version simple.
- Use clear headings.
- Make contact links easy to find.
- Check the site on both desktop and mobile.
- Keep GitHub repository names simple.
- Commit meaningful changes.
- Add projects as you complete them.
- Use accessible text and readable contrast.
- Keep your LinkedIn post factual and concise.
- Check every URL before submitting.

## DON'T
- Don't claim work experience you do not have.
- Don't list technologies you have never used just to look impressive.
- Don't copy another student's portfolio word-for-word.
- Don't publish passwords, API keys or private documents.
- Don't put unnecessary personal information on the site.
- Don't buy a domain just because it looks impressive if the assignment only requires deployment.
- Don't leave broken links in the final submission.

## BEST PRACTICES FOR A BEGINNER
1. One page is enough for version 1.
2. HTML and CSS are enough for this assignment.
3. Use semantic sections such as `header`, `main`, `section`, and `footer`.
4. Use responsive CSS so the site works on phones.
5. Keep CSS organized and use variables for repeated colors.
6. Add real projects when you have them.
7. Improve the portfolio gradually instead of trying to build everything on day one.

## Privacy note
Your phone number and email are public once placed on a public portfolio. If you later become uncomfortable sharing them publicly, replace the phone number with a contact form or a less-sensitive contact method.
