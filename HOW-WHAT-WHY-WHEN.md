# What, Why, When, How — Beginner Guide

## WHAT is a portfolio?
A portfolio is a personal website that introduces you, your skills, education, interests and projects. For a student, it can start simple and grow over time.

## WHY make one?
- It gives you a professional online presence.
- It gives you a project to show in class/interviews.
- It lets you practice HTML, CSS and Git.
- It creates a place where future projects can be added.

## WHEN should you update it?
Update it whenever you:
- finish a project,
- learn a useful skill,
- start a new academic stage,
- complete a certification,
- change your contact links.

A small update every few weeks is better than waiting for a perfect website.

## HOW does the technology work?
- HTML = the structure/content.
- CSS = the visual design/layout.
- Git = version history.
- GitHub = online storage for your Git repository.
- Vercel = hosting/deployment that turns the repository into a public website.
- Domain = a custom web address such as `yourname.com`.

## HOW TO change the portfolio
### Change your name
Open `index.html` and find:
`<h1>Abdurrehman</h1>`

### Change your headline
Find:
`Computer Science Student & Future Developer`

### Change skills
Edit the cards inside the `skills-grid` section.

### Change colors
Open `style.css` and edit the variables near the top:
`--bg`, `--accent`, `--accent-2`, etc.

### Add a project later
Create a new section in `index.html` and give each project:
- Project name
- What it does
- Technologies used
- GitHub link
- Live link

## GitHub concept
A repository is the project folder stored online. A commit is a saved version. A push sends your local commits to GitHub.

## Deployment concept
Vercel connects to your GitHub repository. When you deploy, Vercel builds/serves the files so other people can visit your site.

## Custom domain
A custom domain is optional for a first-day student portfolio. If you later buy one, add it through the hosting provider's Domains section and follow the DNS records they provide. Do not copy random DNS records from tutorials; use the exact records shown by your hosting provider.
